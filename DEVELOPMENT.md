# 👏 Clap Clap — Development

## Layout

```
src/shared/   → ReplicatedStorage.Shared          (Config, Formulas, Num, Format, Sounds)
src/server/   → ServerScriptService.Server        (init.server.luau + services)
src/client/   → StarterPlayerScripts.Client       (init.client.luau + controllers)
build/        → Studio scripts that (re)build the stage worlds into workspace.Stages
tools/        → pacing simulator, checksum sync check
docs/         → design docs
```

`default.project.json` maps the same layout for [Rojo](https://rojo.space), so switching to Rojo later is drop-in.

## Current workflow (no Rojo yet)

`src/` is the source of truth. To push every script into Studio in one go:

```bash
python -m http.server 47811 --bind 127.0.0.1 --directory src
```

then run `tools/studio_sync.luau` in Studio (edit mode, via the Studio MCP `execute_luau`). It
switches HTTP on only for the sync, pulls each file from localhost and restores the setting.
Small one-off edits can still go through `multi_edit`. After a push, compare:

```bash
python tools/checksums.py
```

with the output of `tools/studio_checksums.luau` run in Studio. Every line should match.

World geometry is generated by the scripts in `build/`. Re-running one replaces that stage's model.
`build/stages4to9.luau` builds the City, Region, Country, Planet, Molten and Space stages. To run
one from here, serve the folder (`python -m http.server 47813 --bind 127.0.0.1 --directory build`)
and in Studio edit mode fetch it with `HttpService:GetAsync` and run it with `loadstring`. The
attributes the client reads (`DamageKind`, `Resist`, `Launch`, `React`, `Float`) are explained at
the top of `build/stage3_town.luau` and in docs/10-multiplayer-effects.md.
`build/place_settings.luau` sets place properties the game depends on (StreamingEnabled **off**:
local destruction needs whole stage models on every client) and lists the settings that must be set
by hand after publishing (Max Players 20, Studio API access).

## Saving

`DataService` uses a session lock in the save record so two servers never write the same player at
once: a joining server waits for the previous one to release (force-takes after 30 s), saves only
write while the lock is still ours, and a player is kicked rather than given a blank profile if
loading fails. Unpublished places, or places without Studio API access, use in-memory data.

## Multiplayer test

Studio → **Test** tab → *Clients and Servers* → 2 players → **Start**. Check: both seated in
neighbouring hall seats, each sees the other's arms move with smaller rings, clapping on the beat
together shows **IN SYNC**, the Standing Ovation fires for both, a breakthrough by one player
shows a banner to the other.

**Save the place file** (File → Save to File) as `ClapClap.rbxl` in this folder. The Studio place
holds the built worlds; the scripts can always be re-pushed from `src/`.

## Testing in Studio

- Saving is disabled while the place is unpublished (in-memory data; a warning prints on start).
- Studio-only cheat for fast-forwarding, from the **Server** datamodel during play:
  `game.ServerStorage.DevGrant:Invoke(0, applauseLog10, techniquesUpToStage)`
  e.g. `DevGrant:Invoke(0, 8, 1)` adds 10⁸ Applause and all stage-1 techniques to every player.
  A 4th argument puts the save at exactly that stage (up or back down): `DevGrant:Invoke(0, nil, 6, 7)` = stage-6 techniques, go to stage 7.
  A 5th fills Space's escape velocity: `DevGrant:Invoke(0, nil, 8, 9, 0.99)`.
  A 6th adds currency for the running event: `DevGrant:Invoke(0, nil, nil, nil, nil, 5000)`.
- `game.ServerStorage.DevEvent:Invoke("christmas2026")` forces an event in Studio; `""` goes back
  to the real calendar. Event dates, shops and the "Next update" board times live in
  `src/shared/Events.luau`.
- Studio tests write to the real DataStores (your save and the world leaderboard) once the place is published with API access.
- **Play from a brand-new save without touching yours:** in edit mode run
  `game.ServerStorage:SetAttribute("DevFreshSave", true)`, then Play. Progress stays in memory and
  the world leaderboard is left alone. Run `SetAttribute("DevFreshSave", nil)` to go back.
- `game.ServerStorage.DevOvation:Invoke()` starts a Standing Ovation.

## Tuning

Economy numbers live in `src/shared/Config.luau`. Re-check pacing after changes:

```bash
python tools/pacing_sim.py
```

(`--sloppy` for a weaker rhythm player, `--calibrate` to refit costs to `TARGET_CLEAR_MIN`).
Current target: stage 1 in ~2 min, each stage longer than the last, Space at ~55 min.

## Icons

Menu icons are small 3D models built in code and rendered with Blender (installed at
`C:\Program Files\Blender Foundation\Blender 5.2`; no add-on needed). `tools/icons3d.py` has one
function per icon, made from rounded primitives with glossy materials and a dark outline shell:

```bash
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P tools/icons3d.py
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P tools/icons3d.py -- ui_hands item_pumpkin
python tools/icons.py
```

Blender writes 512px renders to `art/icons/render3d/` (about 40 s for the whole set). `tools/icons.py`
then adds the thick outline and drop shadow, writes transparent 256×256 PNGs to `art/icons/png/` and
saves a contact sheet at `art/icons/sheet.png` for checking by eye. Icons without a 3D render (only
`ui_rays`, the light burst behind items) come from the flat SVG drawings in `tools/icons.py`.

Modelling notes: extruded shapes (`prism`) are built as filled curves, and the outline shell must
not use even thickness, or spiky shapes break. To use a new or changed icon in the game:

1. Serve the PNGs: `python -m http.server 47812 --bind 127.0.0.1 --directory art/icons/png`.
2. Upload them with the Studio MCP `upload_image` tool (`http://127.0.0.1:47812/<name>.png`). The
   images belong to the account signed in to Studio and can show blank for a few minutes while
   Roblox reviews them.
3. Add the returned ids to `art/icons/uploaded.json`, then run `python tools/icons.py --lua` to
   regenerate `src/shared/Icons.luau`, and sync.

Names follow the data: `tech_<id>`, `crowd_<id>`, `stage_<key>`, `item_*`, `cur_*`, `ui_*`.
